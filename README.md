# speedtest.py — замер скорости скачивания

Консольный скрипт: делает N (по умолчанию 10) **последовательных** HTTP(S)-запросов
к одному адресу, каждый ответ дочитывает до конца, затем печатает **среднее время
запроса**, **общий объём** скачанных данных и **скорость скачивания**.

Только стандартная библиотека Python, ничего устанавливать не нужно.

## Требования

Python **3.8 или новее** (набор тестов прогнан на 3.8, 3.9, 3.10, 3.11, 3.12 и 3.13).

```bash
python3 --version        # на Windows: python --version  или  py --version
```

## Запуск

```bash
python3 speedtest.py <URL>
```

На Windows вместо `python3` используйте `python` или `py`:

```bat
py speedtest.py https://example.com/heavy.jpg
```

Пример:

```bash
python3 speedtest.py https://registry.npmjs.org/typescript/-/typescript-5.4.5.tgz
```

Берите **крупный файл** (хотя бы несколько мегабайт, идеально — 10 МБ и больше): на
мелком время почти целиком уходит на установление соединения, и результат отражает
задержку сети, а не пропускную способность.

Скрипт ничего не сохраняет на диск: тело ответа читается блоками и отбрасывается,
считаются только байты.

### Параметры

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-n`, `--requests` | `10` | сколько запросов сделать |
| `-t`, `--timeout` | `30` | таймаут одного запроса, секунды (см. ниже) |
| `-c`, `--chunk-size` | `65536` | размер читаемого блока, байты |
| `--cache-bust` | выкл. | добавлять к адресу уникальный параметр, чтобы обойти кэш CDN |
| `-h`, `--help` | — | справка |

```bash
python3 speedtest.py https://example.com/heavy.jpg -n 20 -t 60 --cache-bust
```

Адрес можно писать как есть: кириллица в домене и пути, пробелы и `#фрагмент`
обрабатываются автоматически. Если адрес пришлось привести к сетевому виду, скрипт
покажет результат строкой `Запрашиваю: …`. Поддерживаются только `http://` и
`https://`; логин и пароль в адресе (`user:pass@host`) не поддерживаются.

## Единицы измерения

* **Время** — секунды. Отсчёт идёт от начала запроса (включая DNS, установление
  соединения и TLS-handshake) до момента, когда тело ответа прочитано целиком.
* **Объём** — байты; в человекочитаемом виде KiB / MiB по основанию 1024
  (1 MiB = 1 048 576 байт).
* **Скорость** — **Mbit/s** (мегабиты в секунду, основание 1000:
  1 Mbit/s = 1 000 000 бит/с). Так принято у провайдеров, с этим числом удобно
  сравнивать тариф. Рядом в скобках — **MiB/s** (мебибайты в секунду), привычная
  единица для менеджеров загрузок. Соотношение: 8 Mbit/s ≈ 0.95 MiB/s.

Как считается итоговая скорость:

```
скорость = (сумма байт по успешным запросам × 8) / (сумма времён этих запросов)
```

Паузы между запросами в знаменатель не попадают — меряется именно пропускная
способность канала, а не длительность всего прогона. «Среднее время ответа» —
тоже по успешным запросам. Медиана и мин/макс считаются по скоростям отдельных
запросов и показывают разброс.

## Что считается успешным замером

Запрос засчитывается, **только если ответ получен целиком**:

* сервер ответил без ошибки (HTTP 2xx, редиректы выполняются автоматически);
* число прочитанных байт совпало с `Content-Length`;
* chunked-ответ дошёл до завершающего чанка;
* тело непустое.

Это важно: оборванное на середине соединение отдаёт часть файла очень быстро, и
без такой проверки замер показал бы завышенную скорость. Неполный ответ попадает
в ошибки, а не в статистику.

Ошибка отдельного запроса (таймаут, 404, обрыв, пустой ответ, сбой протокола)
печатается строкой `ОШИБКА — …`, прогон продолжается, в итоговые цифры такой
запрос не входит, а код возврата становится `1`.

## Предупреждения в отчёте

После итогов может появиться блок «Предупреждения»:

* **сервер сжал ответ** — несмотря на `Accept-Encoding: identity`. Объём и скорость
  тогда посчитаны по сжатым байтам на проводе (это честная скорость канала, но
  сам файл больше).
* **размер ответа менялся между запросами** — адрес отдаёт динамический контент,
  средние цифры сравнивать осторожно.
* **сервер не сообщил размер ответа** — нет ни `Content-Length`, ни chunked, конец
  тела определяется только закрытием соединения. Полноту такого ответа проверить
  нечем, поэтому при обрыве связи скорость может оказаться завышенной.
* **успешный замер всего один** — результат нерепрезентативен.
* **прогон прерван** — по Ctrl+C; отчёт строится по уже выполненным запросам.

## Важные детали

* **Запросы строго последовательные**: следующий стартует только после того, как
  предыдущий ответ дочитан до конца.
* **Каждый запрос открывает новое соединение** (keep-alive не используется), поэтому
  TCP- и TLS-handshake входят во время каждого запроса. Первый запрос часто
  медленнее остальных: он дополнительно платит за DNS.
* **Таймаут** `-t` ограничивает ожидание соединения и каждого очередного куска
  данных, а кроме того — общую длительность запроса. Общий лимит проверяется после
  каждого полученного куска, поэтому в худшем случае запрос завершится позже `-t`,
  но не более чем вдвое. Время DNS-разрешения под таймаут не попадает — оно
  определяется настройками ОС.
* **Прокси.** Скрипт использует системные прокси из переменных `HTTP_PROXY` /
  `HTTPS_PROXY` / `NO_PROXY` — тогда вы замеряете путь через прокси. Чтобы
  замерить прямое соединение, запустите без них (`NO_PROXY='*' python3 speedtest.py …`).
* `Accept-Encoding: identity` — просим сервер не сжимать ответ, иначе замер шёл бы
  по сжатым байтам вместо размера файла.
* `Cache-Control: no-cache` снижает шанс получить ответ из промежуточного кэша.
  Против кэша CDN надёжнее флаг `--cache-bust`.
* **Потоки вывода.** Весь отчёт, включая строки `ОШИБКА — …`, идёт в stdout, так что
  `speedtest.py … > report.txt` даёт самодостаточный файл. В stderr попадает только
  уведомление о нажатии Ctrl+C.
* Ctrl+C не теряет данные: скрипт печатает отчёт по уже выполненным запросам.
* Вывод в `| head` не оставляет трассировки: скрипт тихо завершается с кодом 141.
* Если консоль не умеет кириллицу, текст выводится с подстановкой `?` и не падает.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | все запросы выполнены успешно |
| `1` | были неуспешные запросы (или не прошёл ни один) |
| `2` | ошибка в аргументах командной строки или в адресе |
| `130` | прервано пользователем (Ctrl+C) |
| `141` | получатель вывода закрыл поток (`… | head`) |

## Состав проекта и проверка

| Файл | Назначение |
|---|---|
| `speedtest.py` | сам скрипт |
| `README.md` | эта инструкция |
| `test_speedtest.py` | автотесты (38 тестов) |
| `testserver.py` | локальный сервер, который умеет вести себя плохо; нужен тестам |

Запуск тестов (интернет не нужен, сервер поднимается на локальном порту):

```bash
python3 -m unittest -v test_speedtest
```

Тесты проверяют пункты задания (ровно 10 запросов, последовательность — по времени
выполнения, среднее время, объём, формат скорости) и поведение в сбойных сценариях:
обрыв соединения, chunked-ответ, ответ без указания длины, пустое тело, таймаут,
404/500, редирект и петля редиректов, сжатие, кириллица в адресе, некорректные
аргументы, Ctrl+C, закрытый пайп, консоль без UTF-8.

`testserver.py` можно запустить и вручную, чтобы посмотреть реакцию скрипта:

```bash
python3 testserver.py                      # 127.0.0.1:8765
export NO_PROXY='*'                        # если настроен прокси
python3 speedtest.py http://127.0.0.1:8765/ok          # норма
python3 speedtest.py http://127.0.0.1:8765/truncated   # обрыв → ошибка, код 1
python3 speedtest.py http://127.0.0.1:8765/slow -t 1   # таймаут → ошибка
```

Список всех эндпоинтов — в докстринге `testserver.py`.
